# Sumire — UX/インタラクション仕様

本書は Sumire の UX(ユーザー体験)と UI 仕様を定める。実装はこの仕様に従い、ここで未規定の挙動はそのつど仕様化してから着手する。

実装プロトコル・データ形式・関数名等の **内部仕様** は `architecture.md` に置く。本書からは必要に応じて参照する。

## プロジェクトの起動・作成・選択

### 起動時挙動

- 既定: 何も開かない空状態でウェルカム画面を表示する
- ウェルカム画面の構成:
  - 「最近のプロジェクト」一覧(クリックで開く)
  - 「新規作成」ボタン
  - 「開く」ボタン
- 設定により「最後に開いていたプロジェクトを自動再開」に切替可能(アプリデータディレクトリの `preferences.json`、配置先は `architecture.md` 参照)。既定は OFF。

### 新規作成の手順

1. ウェルカム画面の「新規作成」をクリック
2. **親フォルダ選択ダイアログ**を表示する(複数プロジェクトを束ねるフォルダ=「親フォルダ」を選ばせる意図)
   - 選んだフォルダ自身が既に Sumire プロジェクト(直下に `sumire.json` を含む)の場合はエラートーストで通知し、ウェルカム画面に留まる(プロジェクトの入れ子化を防ぐため)
3. タイトル・著者の入力ダイアログを表示する
   - タイトル入力中はサニタイズ済みのフォルダ名(=これから作られる子フォルダ名)をリアルタイムにプレビューする
   - サニタイズ結果が空文字または過長(240 文字超)になる場合は警告表示し、送信ボタンを無効化する
4. 親フォルダの直下に **`<サニタイズ済みタイトル>/` の子フォルダを新規作成**し、その中に `sumire.json` および最低限のディレクトリ構造(`chapters/`, `characters/`, `worldbuilding/`, `glossary/`, `plot/`, `history/`)+ 空の `memo.md` を生成する
   - 同名の子フォルダが親フォルダ直下に既に存在する場合は「衝突」エラーを表示し、Dialog を保持して別タイトルでの再入力を促す
5. 新しく作られた子フォルダをプロジェクトルートとして開いた状態でメインビューに遷移する
   - `recent.json` に記録されるパスは親フォルダではなく子フォルダのフルパスである

#### サニタイズ規則(タイトル → フォルダ名)

- Windows 予約文字(`<>:"/\|?*`)および ASCII 制御文字(U+0000〜U+001F、U+007F)を除去する
- 末尾の半角スペースとピリオドを除去し、文字列前後の半角スペースも除去する
- 全角スペース(U+3000)・全角記号・日本語文字はそのまま保持する(日本語タイトルを尊重するため)

#### 採らない方針

- **「選択フォルダをそのままプロジェクトルートにする」モード**(2026-05 仕様改訂以前の挙動): 既存の任意フォルダを誤ってプロジェクト化する事故を防ぐため撤廃する。既存フォルダを取り込みたい需要が顕在化した場合は別動線(取り込みウィザード等)で扱う
- **自動サフィックス付与**(衝突時に `(1)`, `(2)` を末尾に付ける): 書き手の意図しない名前のプロジェクトが黙って作られる事故を防ぐため採らない。衝突時は再入力を促す
- **Windows 予約名チェック**(`CON` / `PRN` / `AUX` / `NUL` / `COM1`〜`COM9` / `LPT1`〜`LPT9` 等): 日本語タイトルでは事実上発生せず、実装複雑化のリスクが上回るため持たない。万一引っかかった場合は OS が返す I/O エラーで間接的に検出される

### 開く操作

- ウェルカム画面の「開く」ボタンから選択する
- フォルダ選択ダイアログでプロジェクトフォルダ(=`sumire.json` を含むフォルダ)を選ぶ
- `sumire.json` が見つからない場合はエラートーストで通知し、ウェルカム画面に戻る
- 起動後にプロジェクトを切り替えたい場合は、ヘッダーの「プロジェクトを閉じる」でウェルカム画面に戻ってから操作する(プロジェクト起動中の「開く」メニューは持たない)

### 最近のプロジェクト

- アプリデータディレクトリの `recent.json` に最大 10 件の履歴を保存する(プロジェクト外、アプリ全体設定。配置先は `architecture.md` 参照)
- 各エントリ: フォルダパス、タイトル、最終アクセス日時
- 履歴から開く時、フォルダが存在しない/`sumire.json` が無い場合は警告し、履歴から該当エントリを削除するかユーザーに尋ねる

## 画面レイアウト

全体は左・中央・右の 3 カラム。右カラムはさらに縦二段で、上にメモ、下に設定を置く。

```
┌──────────┬─────────────────────────┬───────────────────┐
│          │                         │ ② メモ書きペイン  │
│  左:     │                         │   採用候補・提案  │
│ ファイル │ ① 本文エディタペイン    │   ストック・自由  │
│ 一覧     │  (メイン)              │   メモ            │
│ ペイン   │                         ├───────────────────┤
│ 260px    │                         │ ③ 設定タブ        │
│ 固定     │                         │  [キャラ][世界観] │
│          │                         │  [用語集][プロット]│
└──────────┴─────────────────────────┴───────────────────┘
```

各ペインは **常駐表示** する。章ファイルを選択しても右下の設定タブは消えず、
直前に開いていた設定ファイルが表示され続ける。逆に設定ファイルを選択しても中央の
本文エディタは保持される。これにより「本文を書きながら右のメモ・設定をチラ見」
のような操作が成立する。

書き手の主たる視線移動は **本文(中央)⇄ メモ(右上)** であり、設定(右下)は章の
冒頭やコンテキストを見直すときに参照する位置づけ。このため右カラムは初期値で
**メモ : 設定 = 70% : 30%** に割る。

サイズ:

- 左カラムは 260px 固定(リサイズ不可)
- 中央カラムと右カラムの幅は初期値 60% : 40%、境界ドラッグで可変
- 右カラム内のメモと設定の高さは初期値 70% : 30%、境界ドラッグで可変
- ペイン位置の永続化は MVP 後の拡張(リロード時は初期値に戻る)

### 左: ファイル一覧ペイン

VS Code のエクスプローラー相当。プロジェクト全体のファイルをフォルダ分類で表示する。

- フォルダ:`chapters/`, `characters/`, `worldbuilding/`, `glossary/`, `plot/`
- 章ファイルは「章グループ」で折り畳み表示できる(後述)
- 各カテゴリ見出しの右端に「+」ボタン。クリックでタイトル入力ダイアログを開き新規ファイルを作成する。章は連番自動採番、設定は連番なし(連番運用は `architecture.md` 参照)
- ファイルクリックで該当ペインに開く(他のペインの内容は維持される):
  - `chapters/` 配下のファイル → ①本文エディタペインに開く
  - `characters/`, `worldbuilding/`, `glossary/`, `plot/` 配下のファイル → ③設定タブの該当タブをアクティブにし、その内容を表示する
- `memo.md` はファイル一覧ペインには表示しない。右上②に常駐するため、左ペインから呼び出す動線が要らないため。
- 「コンテキストに含める」設定が ON のファイルは、ファイル名左に紫の小ドット( `●` )を表示する。
  全カテゴリを横断して、どのファイルが現在の生成リクエストに混入されるかを一覧で把握できる。

### 左下: LLM 切り替えペイン

左カラムの下部に置く、AI プロバイダの切り替え。見出し「LLM 切替」をクリックすると折り畳める。どのプロバイダで生成するか(「現在使うプロバイダ」)を選び、`llama-server` プロバイダではモデルの選択・状態の確認・停止もここで行う。

プロバイダの行は、上から「OpenAI 互換」「OpenAI」「llama.cpp(Sumire が起動)」の順で固定。

- 行の左端の印(`●` / `○`)をクリックすると、そのプロバイダを「現在使うプロバイダ」にする。現在使うプロバイダは `●`(紫)で示す。選択はプロジェクト(`sumire.json`)に保存する
- 行の名前をクリックすると、右下の設定タブが AI 設定画面に切り替わり、そのプロバイダの設定を編集できる。「現在使うプロバイダ」は変わらない
- 行の `▸` をクリックすると、行の下の階層を開く。名前の後ろの括弧は、下の階層のモデルの数
- 「OpenAI 互換」と「OpenAI」の行の下には、AI 設定画面で入力したモデル名を 1 つ表示する
- 「OpenAI」の行には、API キーが未設定のとき「キー未設定」の印を出す

**「llama.cpp(Sumire が起動)」の行**(2026-11-12、`llama-server-provider` spec。内部仕様は `architecture.md`「llama-server プロバイダ」):

- 印をクリックして「現在使うプロバイダ」にしても、`llama-server` は起動しない。起動するのは、提案か情景文を要求したとき(後述「llama-server プロバイダの動線」)
- 行の下の階層には、上から次を出す
  - **状態の 1 行**: 「停止中」「読み込み中…」「準備完了」「失敗」のどれか
  - **「停止」のボタン**: 読み込み中と準備完了のときだけ出す。押すと `llama-server` を止め(読み込み中なら読み込みを取りやめ)、状態は「停止中」になる。GPU メモリをほかの用途に空けたいときに使う
  - **モデルの一覧**: AI 設定画面で指したモデルのフォルダの、直下にある gguf のファイル名を、名前順に並べる。Sumire は絞り込まない
- 一覧のうち、いま使うモデルに印を付ける
- コンテキスト長をまだ決めていないモデルには、「コンテキスト長未設定」と添える。そのモデルは、AI 設定画面でコンテキスト長を入れるまで起動できない
- モデルをクリックすると、そのモデルを「いま使うモデル」にする。選択はアプリ側に保存し、Sumire を終了しても覚えている
  - `llama-server` が止まっていれば、選択を覚えるだけ。次に提案か情景文を要求したときに読み込む
  - 読み込み中か準備完了なら、動いている `llama-server` を止めて、選んだモデルをすぐ読み込み直す。生成中の提案や情景文は中止する(失敗のトーストは出さない)
- 一覧が空のときは、理由に合わせた 1 行を出す(AI 設定画面の一覧と同じ基準)
  - モデルのフォルダが未設定: 「モデルがありません。AI 設定画面でモデルのフォルダを指定してください」
  - フォルダは指定済みで、直下に gguf が無い: 「このフォルダの直下に gguf ファイルがありません」
  - フォルダが無い・読めない: 「モデルのフォルダを読めません: {{message}}」
- 一覧は、次の時機にフォルダの今の中身で作り直す: Sumire の起動時、モデルのフォルダの指定を変えたとき、AI 設定画面の「一覧を読み直す」、この行を展開したとき(展開された状態で表示されたときを含む)、`llama-server` を起動する直前。Sumire の外で gguf を足した・消したあとは、行を畳んで開き直せば一覧に映る
- 行の名前の後ろの括弧は、一覧のモデルの数

### ① 本文エディタペイン

執筆のメイン領域。横書き。一文一行 + 空行多用の Web 小説スタイルを前提とする。

- 縦書きは非対応(将来拡張)
- ルビ表示はカクヨム式記法 `|漢字《かんじ》` をレンダリングする(なろうも同記法を受け付けるため内部表現も同じ)。ルビは書き手が後から振る運用(API 送信時の前処理は `architecture.md` 参照)
- 文字数カウント: ステータスバーにリアルタイム表示(単位や対象スコープは `architecture.md` 参照)

### ② メモ書きペイン

採用候補・提案ストック・自由メモを置くバッファ。プロジェクトに対して 1 ファイル(`memo.md`)として永続化する。

- 提案候補は明示操作(`Alt+M`)で流し込む。挿し絵の情景文も明示操作(`Alt+I`)で追記する(後述「挿し絵の情景文」)。自動流入はしない。
- 自由テキストとしても編集可能。
- 提案 UX(Shift+Enter / Tab 等)はメモエディタでは無効。雑メモ用途のため。
- オートセーブされる。失敗時のみトーストで通知する(成功時は無音)
- 転記時はファイル末尾に追記する。エントリのフォーマット詳細は `architecture.md` 参照

#### 本文からメモへの転送(切り取り)

本文エディタで選択範囲がある状態で `Alt+M` を押すと、その範囲を本文から切り取ってメモ末尾に追記する(提案表示中はそちらが優先される)。

ドラッグ&ドロップでの転送は持たない(本文 → メモ転記の D&D は撤退済み、キーボード操作 `Alt+M` / `Ctrl+PageUp/Down` に集約。エディタ内テキスト D&D の再検証も含めた経緯は `polish-backlog.md` のテキスト D&D 項目参照)。

### ③ 設定タブ

タブ切替で複数種類の設定情報を表示する。タブ構成:

- キャラ設定 (`characters/`)
- 世界観 (`worldbuilding/`)
- 用語集 (`glossary/`)
- プロット概要 (`plot/`)

各タブは「現在開いている設定ファイル」を 1 ファイル分表示する領域。タブ自体には複数ファイルの一覧を持たない。

#### ファイルの粒度は書き手の自由

「キャラ 1 人 = 1 ファイル」と「主要人物をまとめて 1 ファイル」のどちらも Sumire は同等に扱う。
プロンプトに含める順序や見出しの付け方は書き手のセンスに委ねるべき領域なので、
Sumire 側がカテゴリ名やファイル名から自動で見出し(`# キャラ設定: すみれ` のような行)を
**プロンプトに付与することはしない**。書き手がファイル冒頭に `## 主要人物` のような見出しを
書きたければ自分で書く。書きたくなければ書かなくていい。

なお「章ごとに含める設定セットを切り替える」(序章は主人公だけ、第 5 話でライバル登場…)は将来の拡張とする。MVP は各設定ファイルの `includeInContext` 単純トグルで運用し、場面に応じて書き手が手動で切り替える。設定ファイルの命名(プレフィックス番号など)でプロンプト挿入順を制御することは可能(ロード順はカテゴリ順 → ファイル名順、詳細は `architecture.md` 参照)。

- ファイル選択は左のファイル一覧ペインから行う(専用 UI を③に持たない、二重管理を避けるため)
- タブバーは表示専用。タブをクリックしても何も起きない(ナビゲーションは左ペインのみ)
- 左ペインで `characters/alice.md` をクリック → ③の「キャラ設定」タブがアクティブになり、`alice.md` の内容を表示する
- 同じカテゴリの別ファイルを開けば、③の同タブの内容が差し替わる
- 異なるカテゴリのファイルを開けば、③のアクティブタブが切り替わり内容も差し替わる
- 「コンテキストに含める」チェックボックスは各タブ内のヘッダーに表示する。
  ON/OFF 状態の俯瞰可視化はファイル一覧ペインの紫ドットが担う(タブバーには表示しない、二重管理を避けるため)

## 提案 UX(Copilot 風インライン補完)

### 基本フロー

1. 書き手が本文エディタにカーソルを置く
2. 手動トリガー(`Shift+Enter`)で AI に続きの生成を要求する
3. 生成完了後、カーソル位置に提案テキストがインライン表示される(ゴーストテキスト、薄いグレー)
4. キー操作で採用/別案/却下を行う

### 提案の挿入位置

- カーソル位置までを文脈(直前本文)として AI に渡し、続きを生成する
- 提案テキストはカーソル位置に挿入される
- カーソルが文の途中(例:「彼は[カーソル]走った。」)にあっても自動でジャンプはしない。Copilot 流に「ここから続けて」と解釈する
- 採用時(`Tab`)はカーソル位置に提案テキストが挿入され、後続の既存テキストは押し出される

### スクロール追随

- 提案ゴースト表示時、ゴーストの末尾(挿入位置 + テキスト長)がエディタの可視領域に
  入るようスクロールする。提案が複数行のとき、末尾が画面外で見えない事故を防ぐ。
- ストリーミング表示中はチャンク到達ごとにゴースト末尾が伸びるため、末尾位置の変化に
  合わせて追随する。
- 採用時(`Tab`)も、挿入後のカーソル位置を中央寄せでスクロールする。長い提案を
  採用した直後に「続きを書く視界」を確保するため。

### キーバインド

| 操作 | キー |
|---|---|
| 提案を要求(手動トリガー) | `Shift+Enter` |
| 提案を採用(全文挿入) | `Tab` |
| 提案を却下 / 生成中なら停止 | `Esc` |
| 提案候補をメモペインに保存 | `Alt+M`(提案表示中)または選択範囲を切り取って転送(本文選択中) |
| 挿し絵の情景文を生成してメモに追記 | `Alt+I`(本文エディタ。後述「挿し絵の情景文」) |
| 情景文の生成を中止 | `Esc`(提案の生成中でも表示中でもないとき) |
| ペイン間カーソル移動 | `Ctrl+PageDown` / `Ctrl+PageUp`(本文 → メモ → 設定 → … ) |
| 保留中オートセーブの即時フラッシュ | `Ctrl+S` |
| プロジェクトのスナップショット保存 | `Ctrl+Shift+S` |

「全部却下して再生成」専用キーは持たない。`Esc` で却下したあと `Shift+Enter` で再生成すればよい。
別案候補のサイクル機能は持たない。生成方向が見当違いと感じたら `Esc` で停止 → `Shift+Enter` で
別の案を取り直す、または現在の提案を `Alt+M` でメモに退避してから再生成する運用とする。

キーバインドは MVP では固定。定義はコードの一箇所に集約し、将来カスタマイズ可能な土台を残す。

### 提案の長さ(粒度)

- 既定値: 200 トークン程度(text-generation-webui の慣例値)
- 体感としては「次の一文〜二文」程度。LLM の性質に依存する
- 設定で変更可能(`sumire.json` 直編集)
- 思考モデルでは、思考に使ったトークンもこの上限に含まれる。既定の 200 では思考の途中で上限に達することがあるので、1000 前後に設定する(`architecture.md`「思考ブロックの分離」参照)

### 候補数

常に **1 案**。複数案の生成・サイクル比較は持たない。
生成された案が気に入らなければ `Esc` で却下 → `Shift+Enter` で再生成する。
気に入った部分だけ残したい場合は `Alt+M` でメモに退避してから再生成する。

理由:
- ローカル LLM では並列リクエストでも実質 GPU 1 個を取り合うため待ち時間が候補数倍になる
- ユーザーの実運用は「複数回生成して部分部分をメモで組み立てる」スタイルで、メモ経由の動線が
  サイクル比較より太い。サイクル機能が無くても運用は成立する
- ストリーミング + 生成停止の組み合わせで「Esc → Shift+Enter」の再生成サイクルが速い

### 部分採用

MVP 非対応。Copilot の「単語ずつ採用」相当は日本語では文節解析が必要となり MVP スコープを超える。

### 提案のキャンセル挙動

- 提案表示中に文字を入力すると、提案は自動的にキャンセルされる
- 提案表示中にカーソル移動しても自動キャンセル(範囲外に移動した場合)
- ストリーミング生成中に上記が起きた場合は、HTTP リクエストも併せて中断する
  (途中まで届いたテキストは破棄、ゴーストも消える)

### IME(変換中入力)の扱い

IME 変換中であってもゴーストはキャンセルする。ユーザーが IME を起動した時点で「自分で続きを書こうとしている」意思表示と解釈するため、変換確定を待たずに消す方が一貫する(実装上の判断は `architecture.md` 参照)。

### ストリーミング表示

提案テキストはストリーミング受信して、チャンク到達ごとにゴーストを伸ばしていく。書き手は生成途中から内容を読めるため、見当違いの方向に進んだら早期に `Esc` で停止できる(プロトコルは `architecture.md` 参照)。

ストリーミング中の操作:
- `Tab` 採用は **無効**(押されても何も起きない)。完了後に押せば、その時点で確定した
  テキストを採用できる
- `Esc` は **停止**(後述「生成停止」)
- 文字入力 / カーソル移動は **暗黙停止 + ゴースト破棄**(既存のキャンセル挙動と統合)
- `Alt+M` は **無視**(まだ確定していない案をメモに送るのは無意味)

完了後は通常の提案表示状態に遷移し、`Tab` で採用、`Esc` で却下、`Alt+M` でメモ転記、
いずれも従来通り動く。

ゴーストの見た目は、ストリーム中も完了後も「カーソル位置の右に薄いグレーで描画」で同じ。
生成中であることはエディタ右下のインジケーター(既存)で示す。

### 生成停止

ストリーミング中に `Esc` を押すと、生成リクエストを中断し、途中まで届いたテキストを破棄してゴーストを消す(中断手段は `architecture.md` 参照)。

- 中途半端なテキストは採用 UI として残さない(押し間違えで採用してしまうリスク回避)
- 停止後は何も表示されない状態(=提案要求前)に戻る。再生成したければ `Shift+Enter`

`Esc` の挙動はモードで切り替わる:
- 生成中(=ストリーム受信中) → 停止
- 提案表示中(=ストリーム完了後の確定表示) → 却下
- どちらでもない → 何もしない(キーは下層に通る。情景文の生成中なら、その中止に使われる。後述「挿し絵の情景文」)

### 思考中の表示

思考モデルが応答に混ぜる思考ブロック(既定は `<think>`〜`</think>`)は、ゴーストに出さない。思考の中身は書き手に見せず、思考中であることと経過秒数だけを示す(2026-11-01、`thinking-output` spec。分離の規則は `architecture.md`「思考ブロックの分離」参照)。

- 思考ブロックを受信している間、ゴーストの位置に「思考中… N 秒」を表示する。思考の前に本文を受信していればその末尾に続けて、なければカーソル位置に出す
- 思考の前に受信した本文は、ゴーストとして表示したままにする
- 経過秒数は、その思考ブロックが始まった時点から数え、1 秒ごとに更新する。思考ブロックごとに 0 から数え直す
- 終了タグを受信したら表示を消し、続く本文をゴーストとして伸ばす。思考の前後の本文は、前後の改行を多い側の数にそろえてひと続きにする
- 表示はゴーストと同じ色で描き、スクロール追随の対象にする
- `Tab` で採用するテキストと `Alt+M` で転記するテキストに、思考は含まれない

思考中もストリーミング中として扱い、操作は「ストリーミング表示」と同じ:
- `Tab` / `Alt+M` は **無効**。本文がまだ空でも、`Tab` はタブ文字を入れずに吸う
- `Esc` は **停止**。思考の前に受信した本文も含めてゴーストを消す
- 文字入力 / カーソル移動は **暗黙停止 + ゴースト破棄**

思考が終わらないまま応答が終わったときは、思考の前に受信した本文も含めてゴーストを消し、提案を出さない。理由をトーストで示す。

| 状況 | トースト(`ja.json` の文言) |
|---|---|
| 思考の途中で生成の上限(maxTokens)に達した | 思考の途中で生成の上限に達しました。maxTokens を増やしてください |
| 上限以外の理由で、思考が終わらないまま応答が終わった | 思考が終わらないまま応答が終わりました |

どちらも、応答が空のときの「提案を取得できませんでした(応答が空です)」とは別の文言にする。思考がすべて終わったあと、思考を除いた本文が空だったときは「応答が空です」のほうを出す。停止したときはトーストを出さない。

思考を分離するかどうかと、思考とみなすタグの組は、プロバイダごとに `sumire.json` で変える。AI 設定画面には出さない(`architecture.md`「`sumire.json`」節参照)。

### 提案ログ

- 表示中の提案候補をユーザー操作でメモペインに転記できる(キーバインド `Alt+M`)
- 転記対象は現在表示中の提案テキスト
- ストリーミング中の `Alt+M` は無視する(まだ確定していないため)
- 全候補一括の転記や、採用した分だけの自動ログは MVP では持たない
- 自動的な永続ログは持たない(ファイル肥大化を避けるため)
- 転記してもゴーストはそのまま表示され続ける(採用とは独立した操作)
- 通常はメモペイン(`MemoPane`)が常駐しているので、転記先は EditorView に直接挿入する。
  メモエディタが何らかの理由で未マウントの場合のみ、`memo.md` に直接追記するフォールバックが動く。

## 挿し絵の情景文

本文で挿し絵にしたい場面を選んで `Alt+I` を押すと、その場面の情景と構図を日本語の文章(情景文)にまとめ、メモの末尾に追記する(2026-11-05、`illustration-prompt` spec)。書き手は情景文をメモで直してコピーし、ComfyUI の日本語→英語のプロンプト変換ワークフローに渡す。人物の外見などのタグや品質の指定は、これまでどおり書き手が手打ちする。Sumire は ComfyUI を呼ばない。

新しい画面は作らない。起点は本文の選択範囲で、結果はいつものメモに入る。続き提案(ゴースト・`Tab`・`Shift+Enter`・`Alt+M`)の挙動は変えない。プロンプトの形・設定・予算配分は `architecture.md`「挿し絵の情景文」、範囲の判断は `roadmap.md`「挿絵生成」を参照。

### 使える条件

- ローカルの Completion のプロバイダ(OpenAI 互換と、Sumire が起動する `llama-server`)でだけ使える。OpenAI プロバイダ(クラウド)を選んでいるときは、トーストで伝えて生成しない。`llama-server` プロバイダでは、準備完了のときに生成できる。止まっているとき・読み込み中の `Alt+I` の扱いは、続き提案と同じ(後述「llama-server プロバイダの動線」)。
- `sumire.json` に挿し絵用のテンプレート(`illustration.template`)を書いておく。書いていなければ、トーストで伝えて生成しない。設定は AI 設定画面には出さず、`sumire.json` の直接編集だけで変える。書き換えたらプロジェクトを開き直す(`architecture.md`「`sumire.json`」節の `illustration`)。
- 接続先・モデル・思考の分離の設定は、続き生成と同じものを使う。テンプレート・温度・最大トークン・タイムアウト・指示文は、挿し絵用に別に持つ(続き生成は思考なし、挿し絵は思考あり、のように使い分けられる)。

### 起動と場面の決め方

- 本文エディタで `Alt+I` を押す。メモ・設定・履歴プレビューのエディタでは効かない(提案 UX が無効なエディタと同じ)。
- 範囲を選択していれば、選択範囲を場面にする。選択していなければ、カーソルのある行を場面にする(1 行が 1 段落の書き方を前提に、行を段落とみなす)。
- 場面が空白だけ(カーソルのある行が空行など)、または場面がまるごとフロントマターの中にあるときは、生成せずに、場面を選ぶよう促すトーストを出す。
- 場面のほかに、同じ章の中で場面より前の本文と後の本文、「コンテキストに含める」が ON の設定ファイルを、文脈として読ませる。前の本文を厚く、後の本文を薄く読む。今の章より前の章は読まない。
- 文脈がコンテキストに収まらなければ、場面から遠い本文から削る。それでも収まらなければ、設定ファイルを外す。設定の予算(`settingsTokenBudget`)に入らない設定ファイルも外す。どちらで外した設定ファイルも、生成の前に 1 枚のトーストで名前を並べて伝える。場面そのものが収まらなければ、生成せずに、場面を短くするよう促すトーストを出す。
- `Alt+I` を押しても、本文・選択範囲・カーソル位置は変わらない。

### 生成中

- ステータスバーの「生成中…」と同じ並びに、「情景文を生成中… N 秒」を出す。経過秒数は 1 秒ごとに進む。生成が終われば消える。
- 生成中も、本文やメモを入力・編集し、カーソルを動かせる。これらの操作では生成は止まらない(続き提案のような暗黙の停止はしない。結果は本文ではなくメモに入るため)。
- 生成中に別の章を開いても、生成は続く。完了したら、生成を始めた章のファイル名を添えてメモに追記する。
- プロジェクトを閉じると、生成を中止し、メモには何も追記しない。

**`Esc` の優先順位**(本文エディタにフォーカスがあるとき):

| 状態 | `Esc` の結果 |
|---|---|
| 続き提案の生成中・表示中 | 提案の停止・却下を優先する(「生成停止」節のとおり)。情景文を生成中なら、それは続く |
| 提案が無く、情景文を生成中 | 情景文の生成を中止する。メモには何も追記せず、トーストも出さない |
| どちらも無い | 何もしない(キーは下層に通る) |

続き提案の生成と情景文の生成は同時には走らない(下の排他)。提案と情景文の生成が重なるのは、提案を表示したまま `Alt+I` を押したときで、このときの `Esc` は提案を却下し、もう一度 `Esc` を押すと情景文の生成を中止する。

**続き提案との排他**:
- 情景文の生成中に `Alt+I` を押すと、新しい生成は始めず、生成中であることをトーストで伝える。
- 情景文の生成中に `Shift+Enter` を押すと、続き提案は始めず、情景文を生成中であることをトーストで伝える。
- 続き提案の生成中に `Alt+I` を押すと、情景文の生成は始めず、提案を生成中であることをトーストで伝える。提案の生成が終わって表示中なら、`Alt+I` で始められる。

### メモのエントリ

生成が終わると、`Alt+M` の転記と同じ区切りと日時の書式で、メモの末尾に追記する。

```text
***
2026-11-05 10:12
〔挿し絵〕003-雨の橋.md「雨脚が強まる中、リナは崩れかけた橋の中央…」
雨の降りしきる中、崩れかけた橋の中央に、杖を背負った少女が立ち止まっている。…
```

- 1 行目は出所の行。`〔挿し絵〕` に続けて、生成を始めた章のファイル名と、場面の冒頭(先頭 20 文字、超えたら `…`)を書く。後から「どの場面の情景文か」が分かるようにするため。
- 2 行目以降が情景文。思考ありのモデルでも、思考はメモに入らない(思考の分離の設定にそのモデルのタグの組を書いてあること。`architecture.md`「挿し絵の情景文」)。
- 生成の上限(挿し絵用の `maxTokens`)で途中で切れたときは、途中までの情景文を追記し、末尾に `(生成の上限に達したため、ここで途切れています)` の行を足す。
- 出所の行と注記は、表示言語によらず日本語で書く。
- メモペインが開いていればメモエディタに直接追記する(`Alt+M` と同じ)。

### トーストの一覧

文言は `ja.json` の `toast.illustration*` / `toast.suggestionIllustrationBusy` の値(`{{…}}` は補間値)。種類を書いていないものはエラーのトースト。

開始の前(生成中の表示は出さない):

| 状況 | トースト |
|---|---|
| 情景文の生成中に `Alt+I` | 情景文を生成中です |
| 続き提案の生成中に `Alt+I` | 続きの提案を生成中です。終わってからもう一度押してください |
| プロジェクトが開かれていない | プロジェクトを開いてください |
| ローカルの Completion のプロバイダ(OpenAI 互換・`llama-server`)でない | 挿し絵の情景文は、ローカルのプロバイダ(OpenAI 互換・llama.cpp)でだけ使えます |
| `illustration` または `illustration.template` が無い | 挿し絵用のテンプレートが指定されていません。sumire.json の illustration.template にプリセットか自由記述を書いてください |
| `illustration` がオブジェクトでない | 挿し絵用の設定を読めません。sumire.json の illustration はオブジェクトで書いてください |
| テンプレートの指定を読めない | 挿し絵用のテンプレートの指定を読めません。sumire.json の illustration.template には preset か custom のどちらか一方を書いてください |
| 未知のプリセット | 挿し絵用のテンプレートのプリセット「{{name}}」はありません。使えるのは gemma4 / gemma4-think / chatml / chatml-nothink です |
| 本文の差し込み口なし | 挿し絵用のテンプレートに本文の差し込み口 {{slot}} がありません |
| 差し込み口の重複 | 挿し絵用のテンプレートに差し込み口 {{slot}} が 2 つ以上あります |
| 場面が無い | 挿し絵にする場面を選択するか、場面の行にカーソルを置いてください |

開始のあと:

| 状況 | メモへの追記 | トースト |
|---|---|---|
| 場面がコンテキストに収まらない | しない | 場面がコンテキストに収まりません。場面を短くするか、contextWindow か挿し絵用の maxTokens を見直してください |
| 設定ファイルを外した(送信の前) | —(生成は続ける) | コンテキストに収まらない設定を外しました: {{names}}(情報。名前は「、」でつなぐ) |
| 完了 | する | 情景文をメモに追加しました(情報) |
| 情景文の途中で生成の上限に達した | する(途切れた旨の注記つき) | 情景文をメモに追加しましたが、生成の上限で途切れています。挿し絵用の maxTokens を増やしてください |
| 思考の途中で生成の上限に達した | しない | 思考の途中で生成の上限に達しました。挿し絵用の maxTokens を増やしてください |
| 上限以外の理由で、思考が終わらないまま応答が終わった | しない | 思考が終わらないまま応答が終わりました |
| 思考を除いた応答が空 | しない | 情景文を取得できませんでした(応答が空です) |
| 推論サーバーへの接続やリクエストの失敗 | しない | 続き生成と同じ文言(「推論サーバーに接続できません」「応答がタイムアウトしました」など)。続き生成で文言を持たない分類と、それ以外の失敗は「情景文の生成に失敗しました: {{message}}」 |
| `Esc` で中止、プロジェクトを閉じた | しない | 出さない |

続き提案の側:

| 状況 | トースト |
|---|---|
| 情景文の生成中に `Shift+Enter` | 情景文を生成中です。終わってから提案を要求してください |

- 上限で途切れたときは「追加しました」の代わりに途切れのトーストだけを出す(2 枚重ねない)。
- 推論サーバーの失敗の文言と「プロジェクトを開いてください」は、続き生成と共有する日本語の直書きで、英語表示でも日本語で出る(`architecture.md`「挿し絵の情景文」)。
- 失敗や中止のあとは、同じ場面でもう一度 `Alt+I` を押せばやり直せる。自動では再試行しない。

## llama-server プロバイダの動線

「llama.cpp(Sumire が起動)」を現在使うプロバイダにしているときの、書き手から見た流れ(2026-11-12、`llama-server-provider` spec)。Sumire が `llama-server` を起動し、モデルを読み込み、要らなくなったら止める。別のアプリの画面でモデルを読み込み直すことも、コンテキスト長を 2 か所で揃えることも要らない。内部仕様は `architecture.md`「llama-server プロバイダ」を参照。

準備完了のあとの続き提案(ゴースト・`Tab`・`Esc`・`Shift+Enter`・`Alt+M`・暗黙のキャンセル)、プロンプトテンプレート、思考中の表示、挿し絵の情景文(`Alt+I`)は、OpenAI 互換プロバイダのときと同じに動く。

### 使い始める前の設定

AI 設定画面(後述「AI 接続設定 UI」)で、`llama-server` の実行ファイルのパスとモデルのフォルダを指し、使うモデルごとにコンテキスト長を入れる。左ペインでモデルを選ぶ。これらはアプリ側に保存され、どのプロジェクトを開いても同じ設定で使える。

- `llama-server` の実行ファイルは Sumire に入っていない。書き手が自分の GPU に合ったものを用意する。
- コンテキスト長は、書き手が自分の GPU に収まる値を決める。Sumire は指定された値をそのまま使い、自動で別の値には変えない。GPU メモリに収まらない値を入れると、実測では読み込みは失敗せず、生成が遅くなった。Sumire はこの速度の低下を知らせない。メモリが足りずに読み込み自体が失敗したときは、読み込みの失敗として伝える。

### 最初の要求では生成しない

- プロジェクトを開いただけ、プロバイダを選んだだけでは、`llama-server` は起動しない。読むだけ・直すだけの日は GPU を使わない。
- `llama-server` が止まっているときに `Shift+Enter`(または `Alt+I`)を押すと、いま使うモデルの読み込みを始め、「読み込み始めました」のトーストを出す。**その要求では生成しない**。ゴーストも生成中の表示も出ない。
- 読み込みには数秒〜数十秒かかる。その間も、本文の編集・保存・メモ・設定の操作はいつもどおりできる。左ペインの状態は「読み込み中…」になる。
- 読み込みが終わると、「準備ができました」のトーストを出し、左ペインの状態が「準備完了」になる。書き手がもう一度 `Shift+Enter`(または `Alt+I`)を押すと、待たずに生成が始まる。準備完了を待って自動で生成することはしない。
- 設定が足りないとき(実行ファイルのパスが未設定、モデルが未選択、選んだモデルがフォルダに無い、そのモデルのコンテキスト長が未設定)は、読み込みを始めず、何を直せばよいかをトーストで伝える。
- 読み込みを始める直前に、モデルのフォルダを読み直して、選んだモデルのファイルが今もあることを確かめる。一覧を最後に読んだあとで消えた・名前が変わったときは、読み込みを始めず、「モデルのフォルダにありません」のトーストを出す(「読み込み始めました」は出さない)。左ペインの状態は一瞬「読み込み中…」になってから元に戻る。フォルダを読めないときも読み込みを始めず、「モデルのフォルダを読めません」のトーストを出す。
- テンプレートの不備や、場面が空の `Alt+I` のように、もともと送れない要求では読み込みを始めない(それぞれのトーストが先に出る)。

### 読み込み中は断る

読み込み中に `Shift+Enter` や `Alt+I` を押すと、生成せず、読み込み中であることをトーストで伝える。要求を覚えておいて、あとから生成することはしない。読み込みをやめたいときは、左ペインの「停止」を押す。

### モデルの切り替えと停止

- 左ペインで別のモデルを選ぶと、`llama-server` が動いていればすぐ読み込み直す。「読み込み始めました」のトーストが出て、準備ができたらまた知らせる。止まっていれば、選択を覚えるだけ。読み込み直す直前にも、選んだモデルのファイルがフォルダにあることを確かめる。無ければ(またはフォルダを読めなければ)、トーストで伝え、動いていた `llama-server` を止める。
- 切り替えたあとの生成からは、新しいモデルのコンテキスト長でプロンプトの予算を計算する。
- `llama-server` は、次のときに止まる: 左ペインの「停止」、現在使うプロバイダをほかに切り替えたとき、プロジェクトを閉じたとき、Sumire を終了したとき。Sumire が強制終了されたときも、`llama-server` は残らない。
- 止めたとき・切り替えたときに生成中だった提案や情景文は中止する。書き手の操作による停止なので、失敗のトーストは出さない。
- `Esc` や暗黙のキャンセルで提案の生成を止めても、`llama-server` は止まらない。次の要求はすぐ受け付けられる。
- 設定(実行ファイルのパス、追加の起動引数、動いているモデルのコンテキスト長)を変えても、動いている `llama-server` はそのまま。次に起動するときから効く。

### 失敗したとき・終了したとき

- `llama-server` を起動できない(実行ファイルが無い、実行できない)ときと、読み込みの途中で `llama-server` が終了したときは、左ペインの状態が「失敗」になり、トーストで伝える。失敗の手がかりは、AI 設定画面の「サーバーの出力」で確かめる。欄の上に、失敗の説明(起動できなかったときは OS のエラー文、途中で終了したときは終了コード)も出る。
- 準備完了のあとに `llama-server` が終了したときは、状態を「停止中」に戻し、トーストで伝える。自動では起動し直さない。
- 失敗や終了のあとにもう一度要求すると、止まっているときと同じく読み込みを始める(その要求では生成しない)。
- 起動した `llama-server` が確保したコンテキスト長が指定と違ったときは、食い違いをトーストで伝え、プロンプトの予算には実際の値を使う。
- どの場合も、本文の編集・保存は続けられる。

### llama-server のトーストの一覧

文言は `ja.json` の `toast.llamaServer*` の値(`{{…}}` は補間値。`{{model}}` はモデルのファイル名)。「モデルのフォルダを読めません」だけは、AI 設定画面・左ペインと同じ `llamaServer.modelsDirUnreadable` を使う。

| 場面 | 種類 | トースト |
|---|---|---|
| 止まっているときの要求で、読み込みを始めた。動いている間に別のモデルを選んで、読み込み直した | 情報 | {{model}} を読み込み始めました。準備ができたらお知らせします |
| 読み込み中の要求 | 情報 | モデルを読み込み中です。準備ができてからもう一度要求してください |
| 準備完了になった | 情報 | {{model}} の準備ができました |
| 実行ファイルのパスが未設定 | エラー | llama-server の実行ファイルが設定されていません。AI 設定画面でパスを設定してください |
| モデルが未選択 | エラー | モデルが選ばれていません。左ペインでモデルを選んでください |
| 選んだモデルがモデルのフォルダに無い(起動の直前の読み直しで分かったときを含む) | エラー | {{model}} がモデルのフォルダにありません。左ペインでモデルを選び直してください |
| 起動の直前に、モデルのフォルダを読めなかった | エラー | モデルのフォルダを読めません: {{message}} |
| 選んだモデルのコンテキスト長が未設定 | エラー | {{model}} のコンテキスト長が設定されていません。AI 設定画面で設定してください |
| `llama-server` を起動できない | エラー | llama-server を起動できませんでした: {{path}} |
| 読み込みの途中で `llama-server` が終了した | エラー | モデルの読み込みに失敗しました。AI 設定画面の「サーバーの出力」を確かめてください |
| 準備完了のあとに `llama-server` が終了した | エラー | llama-server が終了しました。次に要求したときに読み込み直します |
| 確保されたコンテキスト長が指定と違う | 情報 | コンテキスト長が指定と違います(指定 {{requested}}、実際 {{actual}})。実際の値で計算します |
| アプリ側の設定の保存に失敗した | エラー | llama-server の設定の保存に失敗しました: {{message}} |
| 書き手の操作での停止(左ペインの「停止」、プロバイダの切り替え、プロジェクトを閉じる) | — | 出さない |

- 設定の不足は、上から順に検査し、最初に当たった 1 つだけを伝える。
- 「読み込み始めました」は、起動の直前のフォルダの読み直しが済んでから出る。その間(ふつうは一瞬)にもう一度要求すると、「読み込み中です」のほうが先に出る。
- コンテキスト長の食い違いは、準備完了のトーストの直前に出る。
- 生成そのものの失敗(接続できない、タイムアウトなど)は、OpenAI 互換プロバイダと同じ文言で出る。
- `llama-server` が自分で落ちたとき、生成中だった要求の失敗のトーストと、終了のトーストの両方が出ることがある。

## 章とファイル構造

### 章 = 1 ファイル(投稿単位)

Web 小説の「話/エピソード」一回分=章=1 ファイル。`chapters/001-prologue.md` のように連番付き。

理由: 投稿時の取り扱い(コピペ単位)に直結する。執筆中の長大化を避ける効果もある。

### 章グループ(書籍的な大単位)

書き手が「書籍的に長い章で扱いたい」場合のために、複数の話を束ねる「章グループ」を持つ。

- 章グループはタグ的なメタデータ。ファイル一覧ペインで折り畳み表示の単位となる
- 1 ファイル = 1 章は変更しない(投稿単位を壊さない)
- 章グループ定義は `sumire.json` に記述する
- 例: 「第一部:出会い編」というグループに `001-prologue.md` 〜 `010-departure.md` を紐付け、ペイン上で折り畳む

### シーン分割

シーンの区切りは書き手が空行や `***` などのテキストで表現する。専用の構造化機能は当面持たない。

### 章の並び替え

- ファイル一覧ペイン上でドラッグ&ドロップにより章順を変更できる
- 並び順はファイル名のプレフィックス連番で管理(連番運用と並び替え時のリナンバリング規則は `architecture.md` 参照)

## ファイルの新規作成・削除・リネーム

### 章ファイル

#### 新規作成

- 操作: ファイル一覧ペインの `chapters/` フォルダ上で右クリック → 「新規章」
- フロー:
  1. タイトル入力ダイアログを表示
  2. 連番を自動採番する(既存章ファイルの最大連番 + 1)
  3. ファイル名は `NNN-{タイトルの slug 化}.md` 形式
  4. ファイルを生成し、本文エディタペインで開く

#### 削除

- 操作: ファイル一覧ペインで右クリック → 「削除」
- 確認ダイアログを必ず表示する(誤操作防止)
- 削除実体・連番採番ポリシーは `architecture.md`(ファイル管理の方針)参照

#### リネーム

- 操作: ファイル一覧ペインで `F2` または右クリック → 「名前の変更」
- 連番部分(`001-`)はリネーム不可。タイトル部分のみ編集可能
- 入力された新タイトルでファイル名と `title` フロントマターを同時に更新する(slug 化ルールは `architecture.md` 参照)

### 設定ファイル(キャラ・世界観・用語集・プロット概要)

章ファイルとほぼ同じだが、連番なし。

#### 新規作成

- 操作: ファイル一覧ペインの該当フォルダ上で右クリック → 「新規(キャラ等)」
- タイトル入力ダイアログ → ファイル名は `{タイトルの slug 化}.md` 形式
- ファイルを生成し、③設定タブの該当タブをアクティブにして開く

#### 削除

- 章と同じく確認ダイアログを表示する
- 削除前に「`includeInContext: true` で利用中」の警告を表示する

#### リネーム

- `F2` または右クリック → 「名前の変更」で実行
- ファイル名と `title` フロントマターを同時に更新する

## 設定情報のプロンプト挿入(MVP)

設定タブにある情報(キャラ設定・世界観・用語集・プロット概要)を、AI への生成リクエスト時にどうプロンプトへ含めるかの方針。

- MVP はユーザー手動選択方式を採用する
- 設定タブ内の各ファイルに「コンテキストに含める」チェックボックスを設ける
- チェックされたファイルの内容を生成リクエスト時のプロンプトに自動的に挿入する
- ユーザーは執筆中に必要な設定だけチェックを ON にする

### コンテキスト使用量の表示

- ステータスバーに「設定情報: NNN / 500 tok」を常時表示する
- 上限に対する比率で色が変化する: 〜80% 通常(zinc) / 80〜100% 警告(yellow) / 100% 超(赤)
- 警告ダイアログやトーストでの即時通知は行わない(書き手の集中を妨げないため)
- 推定方式・上限値の変更・超過時の挿入順詳細は `architecture.md` 参照

将来的には自動検出方式(本文中のキャラ名・用語を見て該当設定だけ自動的に含める Lorebook 方式)を検討するが当面の対応外。

## 保存状態の可視化

`architecture.md` で定義する三層の保存モデル(未保存バッファ / オートセーブ / スナップショット)に対応する UI 表示。

- **未保存マーカー**: ファイル一覧ペインおよびエディタヘッダーにおいて、未保存変更があるファイルにはタイトル横に `●` を表示する(VS Code 風)
  - Sumire は中央ペインに常に 1 ファイルしか開かない設計のため「エディタタブ」自体を持たず、エディタ上部のヘッダー行が表示単位となる
  - オートセーブ完了時にマーカーは消える
- **最終オートセーブ時刻**: ステータスバーに「最終保存: NN 秒前」を表示する
  - 編集中(キー入力中)はカウンタ更新を一時停止
  - エラー(書き込み失敗)時は「保存に失敗しました」を赤字で表示し、クリックで詳細を開く
- **スナップショット保存通知**: `Ctrl+Shift+S` 押下時はトーストで「スナップショットを保存しました」と短く通知する

## スナップショット保存(履歴)

- 自動保存はしない。`Ctrl+Shift+S` で明示的にスナップショットを取る
- `Ctrl+S` は保留中のオートセーブを即時フラッシュするだけで、スナップショットは作らない(他エディタの癖で連打されてもスナップショットが積まれないように分離した)
- スナップショットはプロジェクト全体の状態を一括で保存する(本文・設定・メモ含む)
- スナップショットからの復元 UI は履歴一覧の表示と「この時点に戻す」操作のみ提供。差分表示は当面持たない
- 保存先パス・保持件数・既定値は `architecture.md` 参照

## AI 接続設定 UI

MVP では最小 UI のみ提供する。

- 接続先 URL の入力欄
- モデル名の入力欄
- 上記以外の細かいパラメータ(temperature・top_p・max_tokens 等)は `sumire.json` 直編集

将来的にプリセット切替(冒頭執筆向け / 会話シーン向け 等)を追加するが MVP 外。

### llama-server の欄

編集対象が「llama.cpp(Sumire が起動)」のとき(2026-11-12、`llama-server-provider` spec)は、接続先 URL・モデル名・Context Window の欄を出さない。接続先は Sumire が起動のたびに決め、モデルは左ペインで選び、コンテキスト長はモデルごとに決めるため。代わりに次の欄を出す。

| 欄 | 内容 |
|---|---|
| llama-server の実行ファイル | パスの入力欄と「参照」ボタン |
| モデルのフォルダ | パスの入力欄と「参照」ボタン。直下の gguf がモデルの一覧になる |
| 一覧を読み直す | フォルダの今の中身で、モデルの一覧を作り直す。すでに入れてあるコンテキスト長は消えない |
| コンテキスト長 | 一覧のモデルごとに 1 つずつ出す入力欄。一覧が空のときは、理由に合わせた案内を出す(下) |
| 追加の起動引数 | 複数行の入力欄。1 行に 1 つずつ書く。値つきの引数は、名前と値を別の行にする(1 行目に `--flash-attn`、2 行目に `on`)。空行は捨てる。全モデル共通で、次に起動するときから効く |
| サーバーの出力 | `llama-server` が出力した末尾(最大 200 行)を、読み取り専用で表示する。「更新」で読み直す。状態が「失敗」になったときは自動で読み直し、欄の上に失敗の説明を 1 行出す(下) |

- これらの欄の値は、プロジェクト(`sumire.json`)ではなくアプリ側に保存する。PC に固有の値なので、どのプロジェクトを開いても同じ値が出る。
- 保存は、ほかの欄と同じく入力から 1 秒後の自動保存。保存に失敗したらトーストで伝える。
- コンテキスト長は 1 以上 4294967295 以下の整数だけを保存する。空欄にすると未設定に戻る。それ以外の値(`abc`、`0`、`1.5`、`4294967296` など)は保存せず、欄の下に「コンテキスト長は 1 以上の整数で入力してください」を出す。`preferences.json` を直接編集して上限を超える値を書いても、読み込むときに未設定として扱う。
- モデルの一覧が空のときは、理由に合わせた 1 行を出す。出し分けは、入力中の値ではなく、保存済みのフォルダで決める。
  - モデルのフォルダが未設定: 「モデルのフォルダを指定すると、その直下の gguf ファイルがここに並びます」
  - フォルダは指定済みで、直下に gguf が無い: 「このフォルダの直下に gguf ファイルがありません」
  - フォルダが無い・読めない: 「モデルのフォルダを読めません: {{message}}」
- 追加の起動引数は、1 行がそのまま 1 つの引数になる(行の中の空白では分けない)。`--flash-attn on` のような値つきの引数を 1 行に書くと、空白を含んだ 1 つの引数として渡り、意図したとおりには解釈されない。欄の下の案内に、2 行に分ける例を出す。
- 状態が「失敗」の間は、「サーバーの出力」の欄の上に、失敗の説明を 1 行出す: 起動できなかったときは「起動できませんでした: {{message}}」(`{{message}}` は OS のエラー文)、読み込みの途中で終了したときは「読み込みの途中で終了しました(終了コード {{code}})」(終了コードが分からなければ「不明」)。起動できないときは `llama-server` の出力が 1 行も無く、出力の欄だけでは理由が分からないため。
- 「サーバーの出力」を読めなかったときは、欄の中に「サーバーの出力を読めません: {{message}}」を出す。
- フォルダからファイルが無くなっても、そのモデルに入れたコンテキスト長は消さない(ファイルを戻せば、値が残っている)。
- 「サーバーの出力」は、読み込みに失敗したときに原因を確かめるための欄。メモリに持つだけで、ファイルには残さない。
- 生成パラメータ・設定のトークン予算・システムプロンプトの欄は、ほかのプロバイダと同じものを出し、プロジェクト(`sumire.json`)に保存する。テンプレート・思考の分離・挿し絵の設定は、ほかのプロバイダと同じく `sumire.json` の直接編集で変える。
